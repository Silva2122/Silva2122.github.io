# CLAUDE.md

Инструкция для Claude Code (claude.ai/code) по работе с этим репозиторием.
Человеческая версия — в [README.md](README.md), инструкция владельцу сайта — в [admin/README.md](admin/README.md).

## Что это за проект

**axelnn.ru** — интернет-магазин товаров для фигурного катания (Нижний Новгород).
Действующий сайт работает на Bitrix + шаблон Aspro Next; здесь новый сайт, написанный
с нуля, и админка, через которую владелец правит его сам.

Бандлера нет: чистый HTML + CSS + vanilla JS. `package.json` держим ради трёх
devDependencies (`sharp`, `playwright-core`, `@huggingface/transformers`) — они нужны
инструментам, а не сайту. Скрипты — ESM, Node ≥ 18. Разработка на Windows.

| Слой | Где | Что это |
| --- | --- | --- |
| **Сайт** | `index.html`, `catalog/`, `company/`, `help/`, … + `assets/` | Статика: то, что уезжает на хостинг |
| **Контент** | `content/*.json` | Данные сайта, которые правит владелец |
| **Админка** | `admin/` | Отдельный модуль: сервер, API, интерфейс |
| **Сборка** | `tools/*.mjs` | Генераторы страниц + сервер, скриншоты, аудит |
| **Архив** | `tools/donor/`, `old_version/` | Эпоха переноса со старого сайта. Для сборки не нужны |

Правки админки и правки сайта — **разные истории**: код админки живёт в `admin/`,
код сборки в `tools/`, и смешивать их в одних файлах не нужно.

```text
axelnn/
├── index.html            главная; она же источник шапки и подвала для всех страниц
├── catalog/ cart/ …      страницы сайта (часть генерируется, часть написана руками)
├── assets/               css, js, картинки, products.json (манифест каталога)
├── content/              ← данные: товары, разделы, контакты, очередь правок текста
├── admin/                ← админка: server.mjs, api.mjs, auth.mjs, images.mjs, publish.mjs, ui/
├── tools/                ← сборка сайта: build-*.mjs, content.mjs, pages.mjs, typo.mjs, visible.mjs
│   └── donor/            ← архив: краулер, парсеры, конвейер кадров
└── old_version/          зеркало старого axelnn.ru (1,9 ГБ, в .gitignore)
```

## Страницы

```text
/                     главная
/catalog/             витрина 14 разделов
/catalog/<раздел>/    товары раздела, подразделы — якорями внутри
/catalog/<раздел>/[<подраздел>/]<id>/   страница товара (1142 штуки)
/cart/  /favorites/
/services/  /help/[delivery|payment|warranty]/  /company/[licenses|rekvizity|reviews|vacancy]/
/contacts/  /info/brands/
/admin/               админка (на сайт не выкладывается, работает только с запущенным сервером)
```

**Показываем не весь каталог.** Товар без фотографии скрыт: карточка-плейсхолдер —
дыра в сетке, а страница товара с пустой галереей не нужна ни людям, ни поиску.
К этому добавились два выключателя из админки: `hidden` у товара и `hidden` у раздела —
закрытый раздел уносит с собой и свои товары, иначе они пропали бы из меню, но собственные
страницы получили бы и открывались по прямой ссылке.

Критерий один на оба генератора и лежит в [tools/visible.mjs](tools/visible.mjs).
Автоскрытие снимается флагом `HIDE_NO_PHOTO`. Сейчас скрыто 254 товара из 1248
и вместе с ними раздел «Подарочные наборы тренерам» (фото нет ни у одного товара).
Руками нигде ничего не перечислено: меню, витрина и страницы собираются из видимых
товаров, так что вернувшееся фото возвращает и товар, и его раздел.

## Команды

```bash
npm run admin                 # админка + сайт: http://127.0.0.1:4180/admin/
node admin/server.mjs --set-password   # сменить логин и пароль владельца

npm run build                 # собрать сайт целиком (шаги ниже в правильном порядке)
node tools/build-pages.mjs    # тексты страниц и контакты из content/
node tools/build-catalog.mjs  # меню, шапка/подвал везде, витрина, разделы, /cart/, /favorites/
node tools/build-products.mjs # 1142 страницы товаров
node tools/build-sitemap.mjs  # sitemap.xml — обходит уже собранные страницы, берёт canonical
node tools/build-home.mjs     # подборки на главной («Новинки», «Скидки и акции») из content/home.json

npm run serve                 # только сайт, без админки: http://127.0.0.1:4173
node tools/audit.mjs /путь/   # аудит вёрстки на 4 ширинах
node tools/shot.mjs / --full --w 1440
```

**Порядок сборки обязателен** — `build-pages` → `build-catalog` → `build-products`,
и ровно так его гоняет кнопка «Опубликовать» в админке. Шапка и подвал живут в `index.html`:
`build-pages` правит там телефон и тексты, `build-catalog` разносит шапку с меню по страницам,
`build-products` берёт её уже готовой. Запустишь наоборот — в 1142 страницах товаров окажется
вчерашнее меню и вчерашний телефон. `build-sitemap` идёт последним и от порядка трёх
остальных не зависит по смыслу, но должен запускаться после них: он не считает разделы
и товары заново, а читает `<link rel="canonical">` из уже собранных файлов на диске.

`shot.mjs` и `audit.mjs` **запускай из PowerShell**: Git Bash переписывает аргумент
с ведущим слэшем в путь Windows, и вместо `/catalog/…/23591/` открывается главная.

`shot.mjs` без флагов обновляет только `sheet.png`; для полной страницы нужен явный
`--full --w 1440`, иначе смотришь снимок с прошлого прогона.

**Python в системе не установлен** — `python -m http.server` не сработает. `serve.mjs`
написан на голом `node:http` и экспортирует `startServer()`, которым пользуются
`shot.mjs` и `audit.mjs`.

## Данные сайта: `content/`

Единственный источник правды для всего, что меняется без правки вёрстки.

| Файл | Что внутри | Кто читает |
| --- | --- | --- |
| `content/products.json` | 1248 товаров: цены, наличие, размеры, описания абзацами, кадры, `hidden` | `build-products`, витрина через манифест |
| `content/sections.json` | разделы: `key` (сегмент URL), заголовок, порядок, картинка, `cut`, `hidden` | `build-catalog` |
| `content/site.json` | телефон, почта, соцсети — на весь сайт | `build-pages` |
| `content/pages.json` | **очередь** правок текста с прошлой публикации | `build-pages` |
| `content/.admin.json` | логин, хеш пароля, ключ подписи куки. **В `.gitignore`** | `admin/auth.mjs` |
| `content/.smtp.json` | SMTP-хост/логин/пароль приложения и адрес для заказов. **В `.gitignore`** | `admin/mail.mjs` |
| `content/.yandex.json` | OAuth-токен Метрики/Вебмастера (`metrika:read/write`, `webmaster:hostinfo/verify`), id счётчика и хоста. **В `.gitignore`** | никем из кода сайта — только вручную curl'ом для отчётов по API |
| `assets/products.json` | манифест каталога — производная от `content/products.json` | оба генератора |

Манифест не пишется руками: его переписывает `syncManifest()` из
[tools/content.mjs](tools/content.mjs) при каждой публикации. Формат тот же, что был
у `prepare-product-images.mjs`, — генераторы перехода не заметили.

**Донор для сборки не нужен.** Описания товаров жили в `old_version/products.json` на 90 МБ,
которого нет ни в репозитории, ни на хостинге. `tools/donor/migrate-content.mjs` вынул из него
всё нужное один раз (`--force` — перезаписать). Генераторы читают `content/`, а на донор
откатываются только на чистой копии, где `content/` ещё нет.

Ключ раздела — **сегмент URL** (`figure-skates`), а не имя категории: имена в данных набраны
как придётся («Хранение» против «Хранение/уход за коньками»), а сегмент один и тот же
и в адресе товара, и в адресе страницы раздела. Путь раздела выводится из `p.url` любого
его товара — товар всегда лежит по `/catalog/<раздел>/[<подраздел>/]<id>/`.

## Админка

Модуль в `admin/`, самостоятельный: сервер, API, вход, картинки, публикация, интерфейс.

| Файл | Обязанность |
| --- | --- |
| `admin/server.mjs` | точка входа, HTTP, статика, флаги `--port`, `--host`, `--set-password` |
| `admin/api.mjs` | все маршруты `/api/*` |
| `admin/auth.mjs` | вход: `scrypt`-хеш пароля, подписанная кука |
| `admin/images.mjs` | кадры из админки на тех же `sharp`-настройках, что в сборке |
| `admin/publish.mjs` | конвейер публикации и его лог |
| `admin/mail.mjs` | SMTP-отправка заказов из корзины (`nodemailer`, настройки в `content/.smtp.json`) |
| `admin/http.mjs` | мелочи `node:http`: типы, ответы, чтение тела |
| `admin/ui/` | интерфейс: `index.html`, `app.js`, `style.css` — vanilla JS, как и на сайте |

Наружу модуль торчит **двумя импортами** — `tools/content.mjs` (данные) и `tools/pages.mjs`
(текстовые слоты): тем же пользуются генераторы, и второй копии этих правил быть не должно.

Админка — **не движок сайта, а редактор его исходников**: она пишет `content/*.json` и кадры
в `assets/img/`, а кнопка «Опубликовать» гоняет те же скрипты из `tools/`, что и мы руками.
Отсюда шаг публикации между правкой и сайтом — и отсюда же переносимость: на хостинге
запускается ровно этот модуль (`--host 0.0.0.0`, обязательно за HTTPS).

Устройство, о котором стоит помнить:

- Куку подписываем HMAC вместо списка сессий в памяти — иначе перезапуск сервера
  выкидывал бы владельца из админки посреди правки.
- Всё внутри `/admin/` сервер ищет только в `admin/ui/`: адрес остаётся коротким
  (`/admin/app.js`), а `admin/api.mjs` по HTTP не выкачивается.
- Вне `/admin/` статик-раздатчик `fileFor()` пускает только белый список публичных
  директорий сайта (`PUBLIC_DIRS`/`PUBLIC_ROOT_FILES` в `admin/server.mjs`) — раньше
  отдавался весь `ROOT`, и 30.08.2026 через это утащили `content/.admin.json` (ключ
  подписи куки) и `content/.smtp.json` (пароль почты) прямым запросом. Список расширяй
  только явным добавлением новой публичной директории/файла, не ослабляй проверку в общем виде.
- Заливка кадра — тело запроса целиком, без `multipart`: разбирать границы формы ради
  одного поля незачем, а `fetch(body: file)` шлёт файл как есть.
- Список товаров отдаётся без описаний: 1248 описаний — это два мегабайта на каждый
  запрос списка. Полный товар отдаётся отдельным запросом.
- Публикация идёт в фоне, интерфейс опрашивает `/api/publish`: держать полминуты открытый
  запрос незачем, а вкладку владелец за это время может и закрыть.
- `/api/order` — единственный маршрут без входа в админку: его вызывает форма заказа
  на `/cart/`, не владелец. Стоит **до** проверки `authed` в `admin/api.mjs`, а не внутри
  какого-то из блоков ниже — если однажды понадобится второй публичный маршрут, ему туда же.

### Тексты страниц

Вёрстка внутренних страниц набрана руками, и переносить её в JSON ради админки означало бы
потерять всё, что в ней есть кроме текста. Поэтому правится не страница, а её **текстовые
слоты**: [tools/pages.mjs](tools/pages.mjs) находит по разметке заголовки, лид, абзацы,
пункты списков, подписи фактов (216 мест на 13 страницах) и отдаёт их админке списком полей.

- Слот опознаётся **хешем собственного текста**, а не позицией: позиция сползает от любой
  правки вёрстки, и «второй абзац» уехал бы в чужой абзац.
- `content/pages.json` — очередь: применённая правка оттуда исчезает, и дальше правда
  о тексте живёт в самой странице. Поэтому админка всегда показывает то же, что на сайте.
- Правка, не нашедшая своего места (текст на странице изменился), **не применяется**
  и остаётся в очереди с предупреждением в логе — молча потерянная правка выглядит
  как «админка не работает».
- Куски, целиком состоящие из ссылок (телефон, почта, пара кнопок), в поля не выводятся:
  владелец увидел бы сырую разметку. Их значения правятся в «Контактах».

Владелец пишет обычный текст, а `&nbsp;` расставляет [tools/typo.mjs](tools/typo.mjs)
при сборке: предлоги и короткие местоимения, числа с единицами, сокращения адреса,
пробел перед тире. Правила подогнаны под то, как набрана вёрстка, и проверяются просто —
прогнать текст страницы через админку и убедиться, что `git diff` пуст.

Про регулярки типографики: границу слова ищем через lookbehind, а не группой захвата
(с группой пробел уходит внутрь совпадения, и в цепочке «и по уровню» второй предлог
уже не находится), и **никакого `\b`** — в JS он считает словом только латиницу,
и правило не совпадало ни с «г. Нижний», ни с «на примерку».

Телефон, почта и соцсети правятся отдельно (`content/site.json`) и заменяются по всему сайту
по маске, включая `href="tel:"` и `mailto:`. Хвост после адреса в `mailto:` сохраняется —
у кнопки «Отправить резюме» там стоит `?subject=`.

Текст самой ссылки маска берёт целиком по границам тега (`<a href="tel:…">…</a>`), а не
по шаблону «похоже на телефон, и сразу за ним `<`» — так однажды один раз испорченный текст
(два номера через запятую) навсегда застревал: маска цепляла только хвост вплотную к `</a>`
и первый номер было уже не найти (баг жил на сайте до 2026-08-19). Заменяет только там, где
внутри тега и правда номер (`+…`) или адрес (`@…`) — кнопки-подписи вроде «Позвоните» не трогает.
Страницы товаров и `/cart/` эта маска не покрывает (`sitePages()` исключает `catalog/`), поэтому
там телефон подставляется в шаблон напрямую из `site.phone` при генерации, а не патчится постфактум.

### Картинки из админки

Кадры товара ужимаются теми же `sharp`-настройками, что и в `tools/donor/prepare-product-images.mjs`:
галерея 2400px, карточка 1200px, `fit: inside`, webp q90 (числа подняты с прежних 1000/600
30.08.2026 — на плотных экранах не хватало резкости, особенно в полноэкранном просмотре —
и ещё раз с 1800/900 и качества 80 31.08.2026, когда владелица заметила, что даже это
недостаточно похоже на исходник; выше поднимать уже не даст видимой резкости, только вес).
Разъедься эти числа — залитое из админки фото стояло бы в сетке иначе, чем всё остальное.
Правку числ уже загруженных фото не улучшает: апскейл существующего кадра добавляет не
резкости, а мыла — выигрыш только для того, что зальют заново. Оригиналов повыше разрешением
для старых, перенесённых с донора фото у нас больше нет: `old_version/site/` вычищен.

Имя файла содержит хеш содержимого (`25010-04d96b10.webp`) — новый кадр не подменяет уже
отданный браузерам. Главным становится первый кадр галереи, и при смене порядка `<id>.webp`
пересобирается сам. Фотография в шапке главной подрезается под 2752×1536
(`fit: cover`, `position: attention`): у `<img>` проставлены `width`/`height`, и кадр другой
формы поехал бы вместе со всем первым экраном.

## Как собираются страницы

Сборки нет, но и копипаста быть не должно. Общие куски живут в `index.html` между маркерами,
а `tools/build-catalog.mjs` разносит их по остальным страницам:

| Маркер | Что внутри | Кто пишет |
| --- | --- | --- |
| `ОБЩЕЕ:ШАПКА` | `<header>`, панель корзины, `<script src="shop.js">` | источник — `index.html`, **пишется** во все страницы |
| `ОБЩЕЕ:ПОДВАЛ` | `.footer-wrap` целиком | источник — `index.html`, **пишется** во все страницы |
| `КАТАЛОГ:МЕНЮ` | выпадающее меню каталога | **пишется** генератором во все страницы |

Правила:

- **Внутри маркеров руками не правим** — перезапишется. Правим генератор.
  Исключение — сам `index.html`: он источник шапки и подвала, там и правим.
- Меню каталога `build-catalog.mjs` обновляет **во всех** `.html` сайта: он обходит дерево
  файлов, а не сверяется со списком. Добавил страницу — меню в ней подхватится само,
  если в ней есть маркеры `КАТАЛОГ:МЕНЮ`. `admin/`, `content/`, `tools/` и `old_version/`
  в обход не попадают.
- Страницы, собираемые целиком (разделы, товары, `/cart/`, `/favorites/`), в проходе шапки
  пропускаются — их подписывает комментарий «Страницу целиком собирает…», и шапку они берут
  из `index.html` при своей сборке.
- Ссылки **меню** — абсолютные от корня (`/catalog/...`): страницы лежат на разной глубине.
- Ссылки **шапки и подвала** — относительные, генератор поднимает их на нужное число уровней
  функцией `upN(html, depth)`. Глубина считается от корня: `/catalog/` → 1,
  `/catalog/<раздел>/` → 2.
- Оба генератора не только пишут страницы, но и **сносят те, что скрылись**: страница скрытого
  товара или раздела иначе осталась бы на диске и открывалась по прямой ссылке. Удаляют только
  файлы со своей подписью в комментарии — чужого не тронут. `build-products.mjs` сверяет
  не список скрытых из текущего манифеста, а весь диск: товар, которого больше нет в манифесте
  вовсе (удалили в админке, а не просто скрыли), туда тоже не попал бы, и страница осталась бы
  сиротой навсегда — так уже случилось с 174 страницами до этой правки (2026-08-19).

Порядок разделов, заголовки и картинки берутся из `content/sections.json`. Таблицы `ORDER`,
`TITLES` и `SECTION_IMG` в начале `build-catalog.mjs` остались **запасным вариантом**
для чистой копии, где `content/` ещё не собран.

## Устройство сайта

- **Токены** — CSS-переменные в `:root` в начале [assets/css/style.css](assets/css/style.css).
  Фирменный цвет `--teal: #1690A0`, текст `--ink`, серые заливки `--grey`/`--canvas`.
- **Именование** — BEM: `.card`, `.card__media`, `.card__name--block`.
- **Шрифты** — Montserrat (интерфейс) + Playfair Display (заголовки), с Google Fonts.
  Заголовки — всегда uppercase + `clamp()` для размера.
- **Логотип** — `assets/img/logo.webp`, знак донора с вырезанным фоном. Прозрачность сделана
  порогом по самому тёмному каналу: на белом и `#F7F8F8` идеально, но **на тёмном фоне
  просвечивает белое лезвие конька** — для тёмной плашки нужен отдельный файл.
- **Адаптив** — основа `clamp()`, гриды и `flex-wrap`; медиазапрос добавляем только там,
  где меняется сама раскладка. Опорные пороги:

  | Порог | Что меняется |
  | --- | --- |
  | `620px` | витрина каталога 2 колонки → `auto-fill`; категории 4 в ряд; таблицы перестают ужиматься |
  | `700px` | герой из «фото сверху, текст снизу» в наложение; карточка услуги в две колонки |
  | `760px` | промо-слайд в две колонки |
  | `900px` | фильтры каталога из листа в колонку слева; внутренняя страница в две колонки; страница товара и корзина в две колонки |
  | `1100px` | меню из бургера разворачивается в строку |
  | `1250px` | в шапке появляется телефон |

  Границы пишем как `899.98px` / `900px`, а не `900` / `900`: на ровно 900 срабатывали
  оба запроса сразу.

  Отдельно от ширины — `@media (pointer: coarse)` в конце файла: он разносит зоны нажатия
  до ~44px. Стоит последним намеренно, иначе базовые правила компонентов, объявленные ниже
  по файлу, перебивают его при равной специфичности. Раскрытие мегаменю по наведению
  закрыто в `@media (hover: hover)`.

- **`--header-h`** — высота липкой шапки, её проставляет скрипт замером. От неё считаются
  верх выехавшего меню, отступ якорей подразделов и верх всех липких колонок. Не подбирай
  эти отступы числом: шапка растёт вместе с логотипом на `clamp()` и меняется от 51 до 61px.
- **Safe-area** — мета стоит с `viewport-fit=cover`, поэтому поля контейнера берутся через
  `--pad-l` / `--pad-r` (`max(--gutter, env(safe-area-inset-*))`). Новый полноширинный блок
  верстай через `.container` — тогда вырез учтётся сам.
- **`.ph`** — плейсхолдер вместо фото. Когда появляется настоящая картинка,
  `<span class="ph"></span>` заменяется на `<img class="ph" src="..." alt="...">`
  (класс сохраняется, стили рассчитаны на оба тега).
- **JS** — два места. Inline-скрипт в конце `index.html` копируется генератором на все
  страницы: бургер, фильтры каталога, карусели, промо-карусель, галерея товара. Отдельный
  файл [assets/js/shop.js](assets/js/shop.js) подключён из общей шапки — корзина и избранное.
  Оба генератора берут inline-скрипт срезом от `<script>` до `</script>`, **и закрывающий тег
  ищут от начала самого скрипта**: в шапке есть `<script src="…/shop.js">`, его закрывающий
  тег стоит раньше по файлу, и поиск с нуля давал пустой срез — страницы молча оставались
  без фильтров, каруселей и галереи.

### Корзина и избранное

Хранилища на сервере у них нет, обе сущности лежат в `localStorage` (`axelnn:cart`, `axelnn:fav`).
Товар описан
data-атрибутами на `[data-product]`, кнопки внутри ищут этот контейнер вверх по дереву —
одна разметка работает и в карточке каталога, и на странице товара, и в избранном:

```html
<div class="card" data-product data-id data-name data-price data-img data-url>
  <a class="card__link" …>…</a>
  <button data-add>В корзину</button> <button data-fav>♥</button>
</div>
```

- `data-img` и `data-url` — **пути от корня** (`/assets/…`, `/catalog/…`). Корзина рисуется
  на страницах любой глубины, относительный путь из раздела указывал бы в никуда.
- Карточка не одна сплошная ссылка: `<button>` внутри `<a>` невалиден, поэтому `.card` —
  контейнер, ссылка живёт в `.card__link`. В каруселях главной осталась старая разметка
  (`.card` как `<a>`) — она работает, кнопок там нет.
- Товар с размерами из каталога в корзину не кладётся: кнопка ведёт на страницу товара
  («Выбрать размер»). На самой странице `data-need-size` заставляет выбрать размер.
- Ключ позиции — `id::размер`: один костюм в 128 и 134 это две строки заказа.
- Оформление — форма «Отправить заказ» (имя, телефон) плюс кнопка «Скопировать заказ»
  и телефон как запасной путь. Форма шлёт `POST /api/order` — единственный маршрут
  `admin/api.mjs`, открытый без входа в админку, потому что зовёт его не владелец,
  а посетитель сайта. Письмо уходит через [admin/mail.mjs](admin/mail.mjs) (`nodemailer`,
  SMTP) на ящик из `content/.smtp.json` — файл в `.gitignore`, как и `.admin.json`, там
  пароль приложения почты. Без этого файла на сервере `/api/order` отвечает `503`,
  а форма просит позвонить — молча «заявка принята» не показываем. Скрытое поле
  `company` в форме — ловушка от ботов-заполнителей (не `display:none`, его бот пропустит,
  а `position:absolute` + `clip`), заполненное человеком не бывает.

## Грабли инструментов

- **Windows-путь из `import.meta.url`**: `new URL(u, import.meta.url).pathname.replace(/^\/([A-Za-z]:)/, '$1')` —
  срезает ведущий слэш у `/C:/...`. Без этого ничего не найдётся на диске. У `ROOT` при этом
  **остаётся завершающий слэш** — путь относительно корня получай через `relative(ROOT, p)`,
  а не через `slice(ROOT.length + 1)`.
- **Запуск дочерних процессов — без `shell`**: путь к `node.exe` лежит в «Program Files»
  с пробелом, и оболочка разорвала бы его по пробелу на команду и аргумент.
- Размеры картинок читаются из заголовка файла первыми 64 КБ — не читай файл целиком:
  на 1248 товарах с десятком кадров это десяток гигабайт ради четырёх чисел.
- `audit.mjs` проверяет шрифты через `document.fonts.check(spec, текст)`. **Текст обязателен**:
  Google Fonts режет гарнитуру по `unicode-range`, и без него проверяется латиница —
  на кириллической странице это давало ложное «шрифт не применился».
- JSON контента пишем с отступом (в дифе видно одну строку, а не файл целиком), манифест —
  в строчку: полтора мегабайта отступов в каждом коммите никому не нужны. Запись всегда
  через временный файл и `rename` — обрыв посреди `products.json` оставил бы сайт без каталога.

## Архив: `tools/donor/` и `old_version/`

Эпоха переноса со старого сайта. **Для сборки не нужны**, лежат отдельно, чтобы не мешать.

```bash
node tools/donor/crawl.mjs             # обход axelnn.ru -> old_version/site/
node tools/donor/verify.mjs            # ссылки без файла на диске -> _missing.json
node tools/donor/fetch-missing.mjs     # докачать всё из _missing.json
node tools/donor/extract-products.mjs  # зеркало -> products.json, categories.json
node tools/donor/migrate-content.mjs   # донор -> content/ (разово, --force перезаписать)

node tools/donor/image-audit.mjs       # фон, разрешение, водяные знаки
node tools/donor/pick-objects.mjs      # предметные кадры без людей
node tools/donor/remove-bg.mjs --from objects --n 400 --model birefnet
node tools/donor/apply-nobg.mjs --html # вырезанные -> assets/img/catalog-nobg/
node tools/donor/prepare-product-images.mjs   # кадры товаров -> assets/img/products/
node tools/donor/make-logo.mjs         # логотип из донора
```

- `crawl.mjs` и `fetch-missing.mjs` инкрементальны: файл уже на диске — не перекачивается.
  Цикл `verify → fetch-missing → verify` гоняем, пока «не хватает» не станет нулём.
- `remove-bg.mjs` сегментирует модель через ONNX. Одиночный кадр (`--file /upload/...`)
  **перезаписывает `_report.json`** одним товаром — перед таким запуском сделай копию отчёта.
  И запускай из PowerShell: Git Bash переписывает путь с ведущим слэшем в `C:/Program Files/...`.
- `extract-products.mjs` определяет карточку товара эвристикой: `itemprop="price"` **и**
  маркер детальной страницы Aspro (`element_detail_text` / `JCCatalogElement`). Парсинг
  регулярками, без DOM-библиотек.
- `tools/donor/content.json` — выжимка для главной, которой пользуются `pick-content`,
  `apply-nobg` и `render-home`. Сайт её не читает.
- `old_version/site/` — зеркало на 1,9 ГБ, в `.gitignore`. Восстанавливается краулером,
  пока жив axelnn.ru.
