# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Что это за проект

Редизайн сайта **axelnn.ru** — интернет-магазин товаров для фигурного катания (Нижний Новгород).
Действующий сайт работает на Bitrix + шаблон Aspro Next. Здесь делается новая вёрстка с нуля,
а полная копия старого сайта лежит рядом как донор контента и референс.

| Слой | Где | Что это |
| --- | --- | --- |
| **Новый сайт** | `index.html`, `catalog/`, `company/`, `help/`, … + `assets/` | Статика, которую мы пишем |
| **Донор** | `old_version/site/` | Зеркало живого axelnn.ru (1619 HTML, ~2500 фото). Только читаем |
| **Инструменты** | `tools/*.mjs` | Краулер, парсеры, генераторы страниц, скриншоты, аудит |

**Главная задача — редизайн.** Пишем новый сайт; `old_version/` только читаем как источник
контента и как референс «что было». Ничего в нём не редактируем и не переносим вёрстку Aspro.

Донор докачан **не полностью** — часть страниц и фото ещё подтягивается (`fetch-missing.mjs`).
Отсутствующий файл в `old_version/site/` — это не поломка, а незавершённая выгрузка: структура
каталогов и формат данных уже финальные и не изменятся, добавляется только содержимое.
Из-за этого **не полагайся на `categories.json` как на источник адресов**: у «Одежды MSK»
со 123 товарами страницы раздела на диске нет вовсе. Путь раздела надёжнее выводить из
`p.url` любого его товара — товар всегда лежит по `/catalog/<раздел>/[<подраздел>/]<id>/`.

Бандлера нет: чистый HTML + CSS + inline vanilla JS. `package.json` есть, но только ради
трёх devDependencies (`sharp`, `playwright-core`, `@huggingface/transformers`) — они нужны
инструментам, а не сайту. Скрипты в `tools/` — ESM, Node ≥ 18.

## Страницы

```text
/                     главная
/catalog/             витрина 15 разделов
/catalog/<раздел>/    товары раздела, подразделы — якорями внутри (14 страниц)
/catalog/<раздел>/[<подраздел>/]<id>/   страница товара (1142 штуки, build-products.mjs)
/cart/  /favorites/
/services/  /help/[delivery|payment|warranty]/  /company/[licenses|rekvizity|reviews|vacancy]/
/contacts/[stores]/   /info/brands/
```

**Показываем не весь каталог.** Товар без фотографии скрыт: карточка-плейсхолдер —
это дыра в сетке, а страница товара с пустой галереей не нужна ни людям, ни поиску.
Критерий один на оба генератора и лежит в [tools/visible.mjs](tools/visible.mjs);
скрытие снимается флагом `HIDE_NO_PHOTO` и повторным прогоном обоих скриптов.
Сейчас скрыто 274 товара из 1416 и вместе с ними раздел «Подарочные наборы тренерам»
(в нём фото нет ни у одного товара) — раздел пропал из меню, витрины и с диска.
Ничего из этого не перечислено руками: меню, витрина и страницы собираются
из видимых товаров, так что вернувшееся фото возвращает и товар, и его раздел.

## Команды

```bash
node tools/serve.mjs                 # http://127.0.0.1:4173
node tools/serve.mjs --root old_version/site --port 8080   # копия старого сайта

node tools/build-catalog.mjs         # меню + шапка/подвал везде + витрина + разделы + /cart/, /favorites/
node tools/build-products.mjs        # страницы товаров (после build-catalog.mjs!)
node tools/audit.mjs [/путь/]        # аудит вёрстки на 4 ширинах
node tools/shot.mjs / --full --w 1440
```

**Порядок обязателен**: `build-products.mjs` берёт шапку из `index.html` уже с меню,
которое туда кладёт `build-catalog.mjs`. Запустишь наоборот — в 1142 страницах товаров
окажется вчерашнее меню.

`shot.mjs` и `audit.mjs` **запускай из PowerShell**: Git Bash переписывает аргумент
с ведущим слэшем в путь Windows, и вместо `/catalog/…/23591/` открывается главная.

**Python в системе не установлен** — `python -m http.server` не сработает.
`serve.mjs` написан на голом `node:http` и экспортирует `startServer()`,
которым пользуются `shot.mjs` и `audit.mjs`.

`shot.mjs` без флагов обновляет только `sheet.png`; `full-1440.png` останется с прошлого
прогона. Для полной страницы нужен явный `--full --w 1440` — иначе смотришь старый снимок.

### Конвейер выгрузки

Порядок важен, каждый шаг дописывает результат предыдущего:

```bash
node tools/crawl.mjs            # обход axelnn.ru -> old_version/site/ + _crawl-state.json
node tools/verify.mjs           # ищет ссылки без файла на диске -> _missing.json
node tools/fetch-missing.mjs    # докачивает всё из _missing.json
node tools/extract-products.mjs # парсит зеркало -> products.json, categories.json, products.md
```

`crawl.mjs` и `fetch-missing.mjs` **инкрементальны**: файл уже на диске — не перекачивается.
Цикл `verify → fetch-missing → verify` гоняем, пока «не хватает» не станет нулём.

### Конвейер картинок

```bash
node tools/image-audit.mjs           # -> _image-quality.json: фон, разрешение, водяные знаки
node tools/pick-objects.mjs          # -> _objects.json: предметные кадры без людей
node tools/remove-bg.mjs --from objects --n 400 --model birefnet   # -> .shots/nobg/birefnet/
node tools/apply-nobg.mjs --html     # вырезанные -> assets/img/catalog-nobg/ + правка index.html
node tools/prepare-product-images.mjs  # 1416 карточек -> assets/img/products/ + assets/products.json
node tools/make-logo.mjs             # логотип из донора -> assets/img/logo.webp
```

`prepare-product-images.mjs` делает два набора кадров: `<id>.webp` (600px) для карточек
в сетке и `<id>-1.webp…<id>-6.webp` (1000px) для галереи на странице товара. Второй набор
попадает в манифест полем `gallery`. Обе стадии инкрементальны — файл на диске
не переделывается, для пересборки нужен `--force`.

`remove-bg.mjs` сегментирует модель через ONNX. Одиночный кадр (`--file /upload/...`)
**перезаписывает `_report.json`** одним товаром — перед таким запуском сделай копию отчёта.
И запускай его из PowerShell: Git Bash переписывает путь с ведущим слэшем
в `C:/Program Files/Git/upload/...`, файл не находится.

Вырезано 337 кадров из 1416. Остальным на страницах разделов достаётся оригинал —
это временно, до следующего прогона `remove-bg.mjs`. 274 товара без годного фото вовсе
(все кадры мельче 400px): растягивать мелкий кадр хуже, чем не ставить, поэтому они
скрыты целиком — см. `HIDE_NO_PHOTO` выше. Появится кадр в манифесте — товар вернётся
сам, руками его нигде вычёркивать не надо.

Оба генератора (`build-catalog.mjs`, `build-products.mjs`) не только пишут страницы,
но и **сносят те, что скрылись**: сгенерированную страницу скрытого товара или раздела
прошлый прогон оставил бы на диске, и она открывалась бы по прямой ссылке. Удаляют
только файлы со своей подписью в комментарии — чужого не тронут.

## Как собираются страницы

Сборки нет, но и копипаста быть не должно. Общие куски живут в `index.html`
между маркерами, а `tools/build-catalog.mjs` разносит их по остальным страницам:

| Маркер | Что внутри | Кто пишет |
| --- | --- | --- |
| `ОБЩЕЕ:ШАПКА` | `<header>`, панель корзины, `<script src="shop.js">` | источник — `index.html`, **пишется** во все страницы |
| `ОБЩЕЕ:ПОДВАЛ` | `.footer-wrap` целиком | источник — `index.html`, **пишется** во все страницы |
| `КАТАЛОГ:МЕНЮ` | выпадающее меню каталога | **пишется** генератором во все страницы |

Правила:

- **Внутри маркеров руками не правим** — перезапишется. Правим генератор.
  Исключение — сам `index.html`: он источник шапки и подвала, там и правим.
- Меню каталога `build-catalog.mjs` обновляет **во всех** `.html` сайта: он обходит дерево
  файлов, а не сверяется со списком. Добавил страницу — меню в ней подхватится само,
  если в ней есть маркеры `КАТАЛОГ:МЕНЮ`.
- Шапку и подвал он разносит туда же и по тем же маркерам. Страницы, собираемые
  целиком (разделы, товары, `/cart/`, `/favorites/`), в этом проходе пропускаются —
  их подписывает комментарий «Страницу целиком собирает…», и шапку они и так берут
  из `index.html` при своей сборке.
- Ссылки **меню** — абсолютные от корня (`/catalog/...`): страницы лежат на разной глубине,
  и относительный путь пришлось бы пересчитывать под каждую.
- Ссылки **шапки и подвала** — относительные, генератор поднимает их на нужное число уровней
  функцией `upN(html, depth)`. Считай глубину от корня: `/catalog/` → 1, `/catalog/<раздел>/` → 2.

Порядок разделов в меню и подмены картинок разделов — таблицы `ORDER` и `SECTION_IMG`
в начале `build-catalog.mjs`, с комментарием у каждого исключения.

## Устройство `tools/`

Скрипты дублируют друг у друга три вещи — при правке одной правь во всех:

- **Windows-путь из `import.meta.url`**: `new URL(u, import.meta.url).pathname.replace(/^\/([A-Za-z]:)/, '$1')` —
  срезает ведущий слэш у `/C:/...`. Без этого ничего не найдётся на диске.
  У `ROOT` при этом **остаётся завершающий слэш** — путь относительно корня получай
  через `relative(ROOT, p)`, а не через `slice(ROOT.length + 1)`.
- **`toPath(url)`** — url → путь на диске: `/` → `index.html`, экранирование запрещённых
  в Windows символов, обрезка точек/пробелов в конце сегмента (NTFS их не хранит).
- **`SKIP_RE`** — чёрный список: корзина, авторизация, фильтры, сортировки, utm.

`extract-products.mjs` определяет карточку товара эвристикой: `itemprop="price"` **и**
маркер детальной страницы Aspro (`element_detail_text` / `JCCatalogElement`). Всё остальное
в `/catalog/` c `<h1>` считается разделом, прочее — информационной страницей.
Парсинг регулярками, без DOM-библиотек.

Размеры картинок читаются из заголовка файла первыми 64 КБ — не читай файл целиком:
на 1416 товарах с десятком кадров это десяток гигабайт ради четырёх чисел.

`audit.mjs` проверяет шрифты через `document.fonts.check(spec, текст)`. **Текст обязателен**:
Google Fonts режет гарнитуру по `unicode-range`, и без него проверяется латиница —
на кириллической странице это давало ложное «шрифт не применился».

## Устройство нового сайта

- **Токены** — CSS-переменные в `:root` в начале [assets/css/style.css](assets/css/style.css).
  Фирменный цвет `--teal: #1690A0`, текст `--ink`, серые заливки `--grey`/`--canvas`.
- **Именование** — BEM: `.card`, `.card__media`, `.card__name--block`.
- **Шрифты** — Montserrat (интерфейс) + Playfair Display (заголовки), с Google Fonts.
  Заголовки — всегда uppercase + `clamp()` для размера.
- **Логотип** — `assets/img/logo.webp`, знак донора с вырезанным фоном. Прозрачность
  сделана порогом по самому тёмному каналу: на белом и `#F7F8F8` идеально, но **на тёмном
  фоне просвечивает белое лезвие конька** — для тёмной плашки нужен отдельный файл.
- **Адаптив** — основа по-прежнему `clamp()`, гриды и `flex-wrap`; медиазапрос
  добавляем только там, где меняется сама раскладка. Опорные пороги:

  | Порог | Что меняется |
  | --- | --- |
  | `620px` | витрина каталога 2 колонки → `auto-fill`; категории 4 в ряд; таблицы перестают ужиматься |
  | `700px` | герой из «фото сверху, текст снизу» в наложение; карточка услуги в две колонки |
  | `760px` | промо-слайд в две колонки |
  | `900px` | фильтры каталога из листа в колонку слева; внутренняя страница в две колонки; страница товара и корзина в две колонки |
  | `1100px` | меню из бургера разворачивается в строку |
  | `1250px` | в шапке появляется телефон |

  Границы пишем как `899.98px` / `900px`, а не `900` / `900`: на ровно 900
  срабатывали оба запроса сразу.

  Отдельно от ширины — `@media (pointer: coarse)` в конце файла: он разносит
  зоны нажатия до ~44px. Стоит последним намеренно, иначе базовые правила
  компонентов, объявленные ниже по файлу, перебивают его при равной
  специфичности. Раскрытие мегаменю по наведению закрыто в `@media (hover: hover)`.

- **`--header-h`** — высота липкой шапки, её проставляет скрипт замером.
  От неё считаются верх выехавшего меню, отступ якорей подразделов и верх всех
  липких колонок. Не подбирай эти отступы числом: шапка растёт вместе
  с логотипом на `clamp()` и меняется от 51 до 61px.

- **Safe-area** — мета стоит с `viewport-fit=cover`, поэтому поля контейнера
  берутся через `--pad-l` / `--pad-r` (`max(--gutter, env(safe-area-inset-*))`).
  Новый полноширинный блок верстай через `.container` — тогда вырез учтётся сам.
- **`.ph`** — плейсхолдер вместо фото. Когда появляется настоящая картинка,
  `<span class="ph"></span>` заменяется на `<img class="ph" src="..." alt="...">`
  (класс сохраняется, стили рассчитаны на оба тега).
- **JS** — два места. Inline-скрипт в конце `index.html` копируется генератором на все
  страницы: бургер, фильтры каталога, карусели, промо-карусель, галерея товара.
  Отдельный файл [assets/js/shop.js](assets/js/shop.js) подключён из общей шапки —
  корзина и избранное.
  Оба генератора берут inline-скрипт срезом от `<script>` до `</script>`, **и закрывающий
  тег ищут от начала самого скрипта**: в шапке есть `<script src="…/shop.js">`, его
  закрывающий тег стоит раньше по файлу, и поиск с нуля давал пустой срез — страницы
  молча оставались без фильтров, каруселей и галереи.

### Корзина и избранное

Бэкенда нет, обе сущности лежат в `localStorage` (`axelnn:cart`, `axelnn:fav`).
Товар описывается data-атрибутами на `[data-product]`, кнопки внутри него ищут этот
контейнер вверх по дереву — одна разметка работает и в карточке каталога, и на странице
товара, и в избранном:

```html
<div class="card" data-product data-id data-name data-price data-img data-url>
  <a class="card__link" …>…</a>
  <button data-add>В корзину</button> <button data-fav>♥</button>
</div>
```

- `data-img` и `data-url` — **пути от корня** (`/assets/…`, `/catalog/…`). Корзина рисуется
  на страницах любой глубины, относительный путь из раздела на `/cart/` указывал бы в никуда.
- Карточка перестала быть одной сплошной ссылкой: `<button>` внутри `<a>` невалиден,
  поэтому `.card` — контейнер, ссылка живёт в `.card__link`. В каруселях главной осталась
  старая разметка (`.card` как `<a>`) — она работает, кнопок там нет.
- Товар с размерами из каталога в корзину не кладётся: кнопка ведёт на страницу товара
  («Выбрать размер»). На самой странице `data-need-size` заставляет выбрать размер,
  иначе заказ пришлось бы уточнять звонком.
- Ключ позиции — `id::размер`: один костюм в 128 и 134 это две строки заказа.
- Оформление — кнопка «Скопировать заказ» и телефон. Формы с «заявка принята» нет
  намеренно: отправлять её некуда.

Фото товаров: вырезанные — `assets/img/catalog-nobg/` и `assets/img/products/`,
оригиналы-заглушки — `assets/img/catalog-raw/`. Тексты и цены — `assets/products.json`
(генерируется) или `old_version/products.json`.

## Известные хвосты

- **274 товара и раздел «Подарочные наборы тренерам» скрыты** — до фотосъёмки их
  на сайте нет вовсе. Возвращаются сами, см. `HIDE_NO_PHOTO`.
- **Inline-скрипт синхронизируется только в генерируемые страницы.** В `company/`,
  `help/`, `services/`, `contacts/`, `info/` он лежит копией с прошлой правки: маркеров
  вокруг него нет. Шапка, подвал и меню в них обновляются, скрипт — нет. Правишь
  inline-скрипт — либо разнеси руками, либо заведи для него маркеры.
- 3 раздела каталога стоят на оригинальных кадрах (одежда для мальчиков, MSK,
  командный стиль): их снимали на моделях, `pick-objects` такие отсеивает.

## Язык
